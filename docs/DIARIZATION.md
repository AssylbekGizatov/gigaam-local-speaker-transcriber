# Диаризация: режим и ограничения v0.2.0

Приложение использует закреплённые локальные ONNX-модели pyannote segmentation 3.0 и WeSpeaker ResNet34-LM через ONNX Runtime CPU. GigaAM Multilingual 220M CTC и его веса не заменены. Обоснование выбора и лицензии: [исследование](DIARIZATION_RESEARCH.md).

## Реальный режим работы

Это предварительная **обработка небольших фрагментов**, а не непрерывный streaming decoder диаризации и не скрытая пакетная обработка полной встречи. Один inference worker последовательно обрабатывает сегментацию/голосовые признаки и GigaAM для окна PCM; GUI и захват не ждут этого в обработчике кнопки. Очередь ограничена 48 секундами аудио. Дополнительные вычисления увеличивают задержку; при переполнении показывается предупреждение о пропуске.

При Stop вход выключается, остаток очереди завершается, предварительные поддержанные метки финализируются. Полная акустическая переоценка всей записи не выполняется: для неё пришлось бы сохранять всю встречу, чего режим без записи аудио не делает. «Завершено» не означает доказанную правильность говорящего.

## Две дорожки и одна нумерация

`source` — `microphone` или `system`. `speaker_id` — анонимный номер в общей session registry. Количество дорожек не равно количеству людей. Один микрофон может слышать нескольких людей; системный звук может содержать многих участников.

Сравнение использует акустические embeddings, без текста и названий языков. Один и тот же голос может получить общий ID в обоих источниках. Разные помещения, кодеки, шум и эхо могут мешать сравнению. Сам по себе переход RU/KK/EN не является правилом создания нового номера. Реальная устойчивость при языковых переходах требует отдельных записей одного человека на разных языках.

Registry живёт до конца сеанса, включая паузы и разрывы временной шкалы. IDs не переиспользуются и не переименовываются при Stop. Новый сеанс создаёт новую нумерацию. Registry ограничена; при исчерпании ресурса новый голос должен оставаться неопределённым с предупреждением, а не переполнять память.

## Слова, эхо и интервалы

Слова GigaAM приходят с локальными CTC start/end. StreamProcessor переносит их на общий абсолютный session clock и применяет владение границами контекстных окон. Фильтр эха сохраняет исходные Word objects/таймкоды; при удалении отдельных повторов остаются точные временные записи сохранившихся слов.

После echo reduction каждое сохранившееся слово связывается с source-specific интервалом говорящего. Слова на неоднозначной границе получают неопределённую метку. Слово не разрезается на копии ради двух интервалов. Соседние слова одного говорящего группируются в реплику; изменение говорящего внутри ASR-фрагмента разделяет его на несколько реплик. Проверяемый инвариант: flattened words после annotation равны исходным words по порядку, тексту и временам — каждый ровно один раз.

Меток для слов без Word timing нельзя восстановить из текста достоверно: такой сегмент остаётся неопределённым. JSON экспорт сохраняет каждую Word запись и отдельно источник, speaker ID, статус и overlap. TXT/MD/DOCX/PDF показывают интервалы реплик, а не всю таблицу времён каждого слова.

Позднее подтверждение эха может удалить ранее показанные микрофонные слова и все связанные с ними разделённые реплики. Системный текст и исходные WAV не изменяются. Эти действия не создают имён людей или независимых транскрипций перекрытия.

## Неопределённость и одновременная речь

Коротких фрагментов может не хватить для надёжного embedding; они остаются неопределёнными. Модель сегментации оценивает несколько локальных голосов и их перекрытия, но не способна гарантировать произвольное число одновременно говорящих. Несколько положительных активностей обозначаются «Перекрывающаяся речь». Если личности этого перекрытия нельзя установить, не создаются фиктивные номера.

GigaAM CTC декодирует один текст из смеси одного источника: сохранение текста не означает разделение обоих голосов. Ошибки диаризации могут быть false merge или false split. Similarity/confidence не является калиброванной вероятностью и не показывается как «процент уверенности участника».

## Приватность

Нет постоянных voice profiles, speaker enrollment, поиска человека по голосу или внешней отправки embeddings. Голосовые признаки находятся только в bounded session registry; PCM не сохраняется для всей встречи без отдельной выключенной по умолчанию опции WAV. Текст/метаданные сеанса растут в памяти. Подкачка ОС, дампы и резервные копии имеют отдельные ограничения: [PRIVACY.md](PRIVACY.md).

## Проверка

Проверяются separately registry rules с синтетическими embedding vectors, реальные inference на разрешённых public recordings, полный путь session/echo/words/export и packaged EXE. Fake tests не являются измерением diarization error rate. Фактические результаты и незавершённые аппаратные/языковые проверки: [TESTING.md](TESTING.md).
