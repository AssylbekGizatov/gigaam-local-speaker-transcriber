# Приватность и границы офлайн-работы

В v0.2.0 speaker embeddings используются только в памяти одного сеанса, не отправляются, не экспортируются и не сохраняются как постоянные voice profiles. Registry содержит до 64 normalized centroids, недавние интервалы ограничены 120 секундами/2048 turns. Полного аудиоархива диаризации нет. Текст и Word metadata растут с длительностью. Source и speaker ID — разные поля; реальных имён или идентификации по внешней базе нет. Stop завершает метки без full-meeting acoustic reanalysis. Подробнее: [DIARIZATION.md](DIARIZATION.md).

Каждый сеанс требует выбора источников, отдельного подтверждения и кнопки «Начать». Проверка уровней тоже требует подтверждения и явно захватывает звук не более 3 секунд. При открытии приложения потоки не создаются. Пауза закрывает оба потока; продолжение только кнопкой пользователя. Автовосстановления записи, фонового автозапуска, аккаунтов встречи и скрытого подключения нет.

Разрешение Windows на микрофон не заменяет согласия участников и требований организации. WASAPI loopback получает все звуки выбранного выхода; отдельный процесс не выделяется. Не используйте захват там, где он запрещён.

## Данные

- Опция аудиофайлов выключена по умолчанию. В этом режиме нет PCM/WAV на диске и нет временных файлов с разговором.
- Обработчик хранит ограниченную очередь до 48 секунд нормализованного аудио по двум источникам. Дополнительно существуют ограниченные очереди драйвера и, только при сохранении аудио, дискового писателя. Текст сеанса остаётся в памяти и растёт с длительностью разговора.
- При включённом фильтре дублей и двух источниках дополнительно используются фиксированные 48-секундные mono 8 kHz буферы каждого источника, вместе с метками валидности 9 216 000 байт. Недавний контекст слов ограничен 64 фрагментами на источник и 128 словами на фрагмент. Всё остаётся в памяти и очищается после завершения обработки при остановке. На диск этот буфер не сохраняется. Подтверждённые дубли удаляются только из итогового текста; необязательные WAV остаются исходными. Подробности и ограничения: [ECHO.md](ECHO.md).
- При сохранении аудио создаётся новая папка и отдельные WAV-фрагменты; паузы/разрывы описаны в timeline.json. Ошибка диска останавливает сеанс явно. После аварийного завершения последний WAV может иметь незавершённый заголовок; timeline не гарантируется.
- TXT/MD/DOCX/PDF/JSON создаются только при экспорте, без промежуточных файлов с текстом. Существующие файлы не перезаписываются. UNC и явно сетевые диски не принимаются; выбранная локальная папка всё равно может синхронизироваться другими программами.
- Диагностический журнал разговоров не создаётся, распознанный текст и аудио не отправляются. Отчёт самопроверки содержит только публичную тестовую фразу и технические результаты, не пользовательские записи.

Python не гарантирует надёжного стирания старых копий памяти. ОС может перенести память в pagefile, создать дамп; антивирус, индексация, резервное копирование и OneDrive могут обрабатывать локальные файлы. Приложение не отключает эти механизмы и не меняет безопасность Windows. Выбирайте каталог хранения и правила удаления самостоятельно.

## Сеть

Обычный запуск не содержит загрузчика модели, облачного STT/LLM, HTTP-сервера или телеметрии. Модель читается напрямую с локального диска и проверяется SHA256. Отсутствующие/изменённые файлы вызывают ошибку. Сетевые Python socket connect/connect_ex/sendto/sendmsg и DNS запрещены в процессе до импорта сторонних библиотек; попытки подсчитываются без адресов или содержания.

GigaAM распознавание использует прежний native Torch/Torchaudio CPU float32. Локальная диаризация дополнительно использует ONNX Runtime 1.23.2 с явно выбранным CPUExecutionProvider и отключёнными telemetry events. Оба ONNX файла локальные и проверяются SHA256. Python ONNX tooling, unused GigaAM ONNX/VAD, CUDA, soundfile и Sherpa/TTS/eSpeak runtime исключены. Native runtime всё равно имеет границы проверки: отсутствие внешних обращений нельзя вывести только из spec или guard.

Это дополнительная защита приложения, **не Windows Firewall**: нативные DLL могут обойти Python API. Проверка сети использует обзор импортов/кода, тест блокировки, счётчик попыток и выборку TCP/UDP endpoints по PID EXE во время самопроверки. Выборка не видит короткие соединения между опросами, системные запросы через общий процесс или все возможные пути нативных библиотек. Полную гарантию отсутствия сети даёт контролируемая среда без сетевого адаптера; без такой проверки в отчёте она не заявляется.

Получение wheels, исходников, лицензий, модели и тестового примера выполняют отдельные build-скрипты. Во время работы GUI они не вызываются. Репозиторий публикует исходники и технические отчёты; разговоры, выбранные устройства, личные папки и локальные настройки туда не входят.

Расширенный dependency inventory включает сборочное окружение, acquisition-записи и полные лицензии, в том числе ONNX/ONNXRuntime и soundfile, установленные для зависимостей upstream. Эти сведения не являются списком библиотек, исполняемых приложением: CPU ONNX Runtime намеренно поставляется для speaker models; manifest и PE-аудит описывают фактический состав frozen-бандла. Публичные отчёты используют версии, имена файлов внутри бандла и SHA256; имя компьютера, абсолютные пользовательские пути и содержимое разговора в них не включаются.
